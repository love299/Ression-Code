# 机器学习科研指标迭代优化专家

## 启动边界

仅在用户明确要求本 Skill 开展项目优化时修改实验副本和运行训练；用户通过自然语言明确要求回归指标迭代优化也构成调用，不要求必须输入美元符号。自动识别相关话题不等于获得训练授权。创建、安装、验证或解释本 Skill 不运行模型。已有明确授权不重复询问。缺少项目路径、数据访问或必要运行资源时，先完成只读定位，再只询问阻塞项。

目标：优先提高验证集 R²，同时保证 Pearson 没有明显下降，尽可能降低 RMSE 和 MAE。不承诺一定改善；没有合格候选时交付原始基线。

## 不可省略的工作模式

原始模型测试 → 建立基线 → 提出一个优化方案 → 只修改一个因素 → 重新训练 → 对比指标 → 决定保留或回滚 → 继续下一个优化方案。

- 每次只允许尝试一个独立的优化因素。
- 禁止一次性修改多个模块。
- 优先进行局部、小范围修改。
- 禁止未经授权进行项目重构。
- 不得删除或覆盖原始代码与数据。
- 每次修改都必须实际运行实验。
- 只有验证集 R² 确实提高，并且 Pearson 没有明显下降，才能接受修改。
- 如果 R² 没有提升，立即撤销本次修改。
- 如果实验失败，恢复到上一个最优代码版本。
- 保留所有失败实验的记录。
- 每次新实验都从当前最优版本开始。
- 不能通过数据泄漏或反复使用测试集来制造虚假的指标提升。

## 1. 只读定位与保护现场

阅读项目指令、依赖、训练脚本、配置、数据加载和评估代码，定位实际训练入口、输出路径、模型选择逻辑和数据划分。不要猜测入口或伪造命令执行结果。

记录 Git HEAD、`git status --porcelain`、已暂存和未暂存的 Git Diff、相关未跟踪文件。保存当前工作目录相关代码的逐字节快照、文件清单和 SHA-256；基线包括用户未提交的修改，不能只按 HEAD 建立副本。保护敏感数据，日志不包含密钥或不必要的样本内容。

所有候选均在独立实验目录中运行，原始项目保持完整。副本必须包含运行所需的用户当前代码，排除 `.git` 和无关大文件；数据默认只读引用，预处理缓存、检查点和日志写入新的独立路径。检查脚本是否写入原始数据、共享缓存或原项目；无法隔离时先停止相关运行并说明原因。

检查符号链接、硬链接、导入路径和 editable 安装，确保实际加载的是实验副本代码，写入路径不会穿透到原项目。不要把副本建在会被递归复制的源目录内。使用现有环境；需要新增依赖时在隔离环境中安装，不擅自升级用户环境。快照涵盖必要的忽略文件和本地模块，但不复制凭据或整套环境。Diff 仅比较代码与配置，运行产物单独保存。

禁止未经允许提交、推送或执行破坏性 Git 命令；不得用 `reset --hard`、`clean`、强制 checkout、整树 restore 或 stash 来保护或回滚用户工作。不要自动初始化仓库或创建提交。非 Git 项目也用 `git diff --no-index` 比较快照和候选；其退出码 1 表示有差异。Git 不可用时先报告无法满足 Diff 要求，不偷偷改用未说明的替代方式。

## 2. 冻结评估协议并建立基线

训练前写入实验协议：数据版本/哈希、样本 ID、训练/验证划分或折分、目标列、特征集、训练命令、依赖版本、硬件、随机种子、预算、指标汇总规则和接受阈值。划分须符合独立样本、分组或时间顺序约束；同组样本不得跨集合，时间任务不得用未来数据训练过去。

首次建立协议前读取 [references/evaluation-protocol.md](references/evaluation-protocol.md)。分别固定 split_seed 与 model_seeds，将实际样本 ID 划分保存到文件；重复训练只改变模型随机种子，不重新切分数据。交叉验证固定同一折清单和每折早停规则，训练内重采样只作用于训练部分。保存重复样本/实体重叠检查结果；不得为提升分数更换验证集。

标准化、插补、特征选择、目标变换等只在训练集或当前折训练部分拟合。验证集用于候选比较；测试集不参与调参、阈值选择、早停或方案排序。审查默认脚本是否自动评估测试集，必要时在统一评估适配层禁用该行为。若现有协议泄漏，先修正协议并重建基线，不能把新旧协议的差异当作模型提升。

在副本上实际运行原始模型，保存训练日志、退出码、耗时、验证预测和真实标签的匹配 ID；不能用论文、旧日志或用户口述数值代替本轮基线。评估适配层如有必要，先独立完成并固定，基线与所有候选共同使用；不要将评估修复与某个优化因素混在一轮。

基线失败或任一必需指标无定义时，不进入优化循环。保留原始失败记录；运行/评估修复单独编号并实际重跑，不能报告为性能提升。涉及目标定义、样本排除、模型改造等语义变化时先取得授权；无法得到有效基线则交付诊断并停止。单纯重算已保存的有效预测不算重新训练，也不能替代修改后的训练。

默认最多 8 个候选方案，基线不算候选。失败、超时、重复方案或另一参数取值也占一个候选名额；同一方案预先规定的重复种子不是新方案。默认每个模型使用配对种子 `[17, 42, 2026]`；确认确定性或资源受限时可预先说明只运行一个固定种子，并披露证据限制。固定 Python、NumPy 和框架种子及数据划分，记录无法消除的 GPU 非确定性。不得事后挑最好的种子。

开始前依据现有训练设置和资源说明单次超时、总训练次数及计算开销；不自动购买计算资源。预算不明且可能超出用户可用资源时询问。达到 8 项、资源上限或无法可靠评估时停止；增加预算必须先获得用户同意。

固定单验证集、三个种子时默认训练上限为 27 次（基线 3 次 + 8 项 × 3 次）；K 折时为 27K 次模型拟合。基线重跑、失败尝试、重复确认和修复运行均计入拟合预算。用户指定更小预算时采用更小值；不能用“重试”绕开上限。基线后按实测耗时更新估计，超出剩余预算时减少候选或停止。超时只终止本会话启动的进程及其子进程，不影响用户其他训练。

## 3. 统一计算真实指标与接受条件

从同一批验证样本的预测计算四项指标，统一在原始目标尺度上评估；目标变换预测先逆变换。禁止按候选结果选择性删样本、裁剪误差或改变聚合方式。

按 `(split_id, fold_id, seed, sample_id, target_id)` 对齐预测，验证键唯一、集合相等、标签一致，不能仅依赖行顺序或 inner join。预测必须来自本次运行的代码/配置/检查点并具有来源记录。缺失预测、重复键、不同标签或过期输出一律判为无效，不做静默补齐。

- R² = 1 − Σ(y − ŷ)² / Σ(y − mean(y))²。
- Pearson = Σ[(y − mean(y))(ŷ − mean(ŷ))] / sqrt(Σ(y − mean(y))² × Σ(ŷ − mean(ŷ))²)，使用有符号的相关系数，不能取绝对值。
- RMSE = sqrt(mean((y − ŷ)²))；MAE = mean(abs(y − ŷ))。
- 少于两个样本、非有限值、恒定目标或恒定预测导致指标无定义时，标记无效，不用 0、1 或库的自动补值伪装通过。恒定预测时即使其他指标可计算，Pearson 无定义也不能接受。
- 多输出任务逐目标记录四项指标，预先冻结主目标或聚合权重；不得观察结果后切换主指标。重复种子/折分记录所有原始值及均值、标准差；R² 和 Pearson 采用预先固定的平均规则。

在看到候选结果前固定判据。默认 R² 最小提升阈值 `epsilon_r2 = 1e-4`，Pearson 最大绝对下降容忍度 `delta_pearson = 0.005`。这是可配置的操作阈值，不是统计显著性的承诺。用户有更严格要求时遵从并记录，不能为了接受失败方案临时放宽。

候选与当前最优版本配对比较，必须同时满足：

1. 所有计划运行成功，指标可定义、预测完整、评估协议一致且不存在泄漏。
2. 平均 R² 的提升严格大于 `epsilon_r2`。
3. 平均 Pearson 的差值不小于 `-delta_pearson`。
4. 多次运行时，每个配对运行的 R² 均提高，Pearson 均未超过下降容忍度；若不满足则以证据不足拒绝，不能从重复运行中挑子集通过。

此外，Pearson 相对初始有效基线 B00 的平均下降也不得超过 `delta_pearson`，防止多轮容忍的小幅下降累积。交叉验证先按固定规则汇总每个种子的折结果，再进行种子间配对判定；保留每折值，不把相关折当作独立重复。第 4 条是默认的保守一致性门槛，不是统计显著性检验；需要其他稳定性准则时只能在看候选结果前设定，并保留 R² 提升与 Pearson 双重约束。只用未舍入数值决策，展示时才四舍五入。

单次结果只能说明该固定运行下的提升。若随机波动大，应对当前最优和候选一同增加预先声明的配对重复；在剩余资源不足时拒绝不确定候选，不宣称显著提升。汇报 RMSE、MAE 的所有变化；它们恶化不应被隐瞒，用户设有误差约束时必须同时满足。固定单目标、样本与权重下 R² 提高而 RMSE 升高，先排查计算不一致，不直接接受。

重复确认的触发条件、额外种子和次数须在候选训练前冻结，只执行一次预定确认批次；不得“跑到通过为止”。扩大种子集时对 B00、当前最优和候选都补齐同样的种子，纳入全部结果重新判定并消耗拟合预算。当前最优在扩大的协议下不再合格时，沿已接受链复核并恢复最近一个合格版本；不足以复核时停止，保留原协议下的结论并标记新证据不足。

Pearson 超过初始基线且满足 R² 条件的候选优先进入后续局部优化；R² 与 Pearson 不保证同时单调增加。MAE 可与 R² 存在权衡，必须显示退步而非宣称四项全面改善。R²/RMSE 一致性检查作用于相同种子、折、目标和权重的单次结果，不能机械地套用到跨折或多输出平均数。带样本权重的项目必须预先固定四项指标的加权定义；上面的公式为无权重情形，不得混用。

## 4. 单因素实验循环

每轮读取 [references/experiment-record.md](references/experiment-record.md)，按其字段持续记录。

1. 基于代码和基线日志提出一个可证伪的局部假设，说明依据、唯一因素、修改位置和预期影响。优先一个文件中的一个超参数、一个现有预处理选项或一个已实现的正则化设置；这些是候选方向，不是必须依次全部执行的清单。
2. 明确唯一因素的旧值和新值。即使在同一个文件里，同时修改学习率和批大小也属于两个因素，必须拆开。不得任意替换模型架构、重构或触碰无关代码；确有必要时先另行取得授权。
3. 从当前最优快照建立新的候选副本，记录父实验 ID 和快照哈希。做最小修改，用 Git Diff 检查只改变一个因素，并保存相对当前最优的补丁以及相对初始基线的累计补丁。不要原地覆盖最优快照。
4. 运行真实训练和固定评估；不得只做静态检查就称为优化成功。语法错误也记为失败，并保存报错。使用独立检查点/输出目录；不得无意复用旧模型预测。除非协议预先统一规定热启动，否则每个候选重新初始化训练。
5. 保存全部日志、命令、预测、指标和退出状态后，按固定判据比较。只有全部通过才将候选标为新的最优版本。
6. R² 不提升、Pearson 下降过多、失败、超时或结果无效时，立即拒绝本次修改：保留失败候选及记录，但活动版本恢复为先前最优快照。这里的回滚只移动实验副本中的活动指针或恢复自己的副本，不修改原始项目或用户暂存区。不能在失败候选上继续优化。
7. 写入保留/拒绝理由，更新预算，再选择下一个有证据支持的因素。不得并行混合候选、暗中网格搜索或在同一编号里反复调参。无合理候选时可提前停止，不必凑满 8 项。

若用户在运行期间修改了原项目，保留其变化，不将旧快照覆盖回去。会话中断后先读取账本、哈希和完成标记；未完整完成的候选不能晋升为最优，须记录中断并恢复先前最优状态。

准备晋升时先写入含新 best_id 的决策记录并完整落盘，再原子更新最优版本清单；清单必须指向完整、哈希匹配的代码与运行产物。重启后核对账本与清单，冲突时恢复最后一个完整确认的最优版本。失败日志与候选留在归档区，活动训练入口只指向最优副本。相同父版本、因素和值不重复尝试，除非存在已记录的外部故障依据；重试仍占预算。

## 5. 交付

交付完整实验账本、固定评估协议、基线与最优指标对照、每轮补丁/日志/预测路径、失败原因、接受链、剩余预算，以及可运行的最优代码副本和复现命令。最优版本必须保留用户原先的相关未提交代码；提供相对初始快照的累计 Git Diff。

默认不将实验副本自动写回原项目。若用户明确要求应用最优修改，先比较原项目当前哈希与启动快照；仅合并自己接受的变更，存在重叠改动时停止写回并说明冲突，不覆盖用户新工作。未经允许不提交或推送。

说明证据来自验证集，且反复选择会导致验证集过拟合；如需最终泛化评估，先冻结最优方案，再在用户授权后一次性评估未触碰的测试集。不得根据测试结果重新进入调参循环。没有任何改进时明确报告并交付基线，不能伪造提升。
