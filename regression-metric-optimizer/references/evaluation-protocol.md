# 评估协议与判定示例

在 B00 之前填好协议；未知项必须明确标为待解决，不能默默使用默认值。运行期间改变评估定义、数据或划分会使旧比较失效，必须保留旧会话并建立新协议，不得拼接两个协议的接受链。

## 协议最小字段

- `protocol_id`、代码/数据清单哈希、目标、原始单位、样本权重定义、验证数据来源。
- `split_manifest`、`split_seed`、分组列或时间截止点、泄漏检查、验证集与测试集职责。
- `model_seeds`、确定性设置、依赖/设备、训练命令、早停监控与耐心值、模型初始化方式。
- `metric_aggregation`：默认单验证集每个种子分别算指标；固定 K 折时先对折指标等权平均得到每个种子指标，再对种子等权平均。若项目采用折大小加权或 OOF 预测整体指标，在基线前固定且全程一致；不能混用折均值 R² 与整体 OOF R²。多目标默认逐目标报告，主判据与权重须明确。
- `epsilon_r2=0.0001`、`delta_pearson=0.005`、Pearson 相对父最优和 B00 的双重下限、用户误差约束。
- `max_candidates=8`、`max_fits`、单次超时、总耗时上限、确认批次触发条件与额外种子（默认不追加）、停机规则。
- 每个新候选的唯一因素及值、父最优、产物位置、完整配对运行清单；在该候选运行前落盘。

默认三种子的所有配对 R² 都上升只是保守稳定性要求；三次成功不能证明统计显著，也不能保证测试集泛化。报告均值、标准差和全部差值，不把这项检查称为显著性检验。

## 决策顺序

1. 先查代码、数据、协议、标签与预测来源；任何不一致都不能通过指标门槛掩盖。
2. 查运行清单完整性：全部预定运行成功才进行晋升，失败或缺失先归档并恢复父最优。
3. 比较未舍入指标：平均 R² 严格提升超过阈值、每个配对 R² 为正提升、每对和平均 Pearson 满足父最优下限、平均 Pearson 满足 B00 下限。
4. 应用用户预设的 RMSE/MAE 限制；无额外限制时如实报告权衡。
5. 保存结论及其依据后晋升或回滚。一个方案失败后，下一项从父最优出发。

## 边界情景检查

这些是规则检查示例，不是科研实验结果，也不能写入真实实验账本。

| 情景 | 必须采取的动作 |
|---|---|
| R² 从 0.80000 到 0.80005，Pearson 提高 | 拒绝：没有超过默认 0.0001 的提升门槛 |
| R² 明显提高，Pearson 从 0.900 降到 0.894 | 拒绝：超过父最优下降容忍度 |
| B00 Pearson 为 0.900，父最优 0.896，候选 0.892 | 即使相对父最优只降 0.004 也拒绝：相对 B00 已降 0.008 |
| 三种子平均 R² 提高，但其中一对下降 | 默认拒绝为证据不足，不能只展示平均值或换掉该种子 |
| R² 提高、Pearson 合格、MAE 恶化 | 检查用户误差约束；没有约束时可接受，但明确记录 MAE 权衡 |
| 预测行数一样但 sample_id 集合不同 | 判为无效，不能直接按行计算或只取交集 |
| 原始模型预测为常数，Pearson 未定义 | 停止优化循环，先诊断基线，不能把 Pearson 填 0 后继续 |
| 第 8 项训练失败，需要再改一个参数重跑 | 失败计入名额；第 9 项先取得预算授权 |
| 训练结束但指标文件未写完时中断 | 候选不晋升，按账本恢复最后完整的最优版本 |
| 用户在实验期间修改了原项目同一文件 | 保留其文件，最优副本单独交付，禁止整文件覆盖回写 |
